# Лабораторна робота № 2. Модульне тестування бізнес-логіки засобами Vitest

**Варіант 1:** функція `applyLoyaltyPoints(total, points)` — списання бонусних
балів (1 бал = 1 грн, не більше ніж 30 % суми замовлення; від’ємна кількість
балів — виняток).

**Стек:** TypeScript, Vitest 5, V8 coverage.

## 1. Що в проєкті

| Частина | Що демонструє | Файли | Тести |
|---|---|---|---|
| 1 | Показовий приклад: розрахунок замовлення | `src/order.ts`, `tests/order.test.ts` | 23 |
| 2 | Індивідуальний варіант 1: бонусні бали | `src/order.ts` (`applyLoyaltyPoints`), `tests/loyalty.test.ts` | 26 |
| Експеримент | Службовий набір без тверджень | `tests/experiment/no-assertion.test.ts` | 2 |

- **Частина 1** перевіряє підсумок позицій, знижку за рівнем клієнта, велике
  замовлення, доставку та підсумкову суму.
- **Частина 2** перевіряє правило «1 бал = 1 грн», ліміт 30 %, межові значення,
  дробові суми, некоректні дані та сумісність із `calcOrderTotal`.
- **Експеримент** показує, що тест без тверджень може підняти покриття, але не
  перевіряє поведінку. У звичайний `npm test` цей набір не входить.

## 9. Налаштування покриття

У `vitest.config.ts`:

- `include: ['src/**/*.ts']` — вимірюється покриття всього модуля;
- `thresholds` — 90 % для statements, branches, functions і lines;
- окремий поріг для `src/order.ts` — щоб регресія в модулі не маскувалася;
- `reporter: ['text', 'html', 'json', 'json-summary', 'lcov']` — текстовий,
  HTML- та машинний звіти;
- для `npm run experiment*` пороги вимкнені, бо мета — показати прогалину, а не
  провалити прогін.

## 10. Корисні правила тестування

- **Грошові суми** порівнюйте через `toBeCloseTo(expected, 2)`, а не `toBe`:
  обчислення з рухомою комою дають наближені значення.
- **Виняток** перевіряйте через функцію: `expect(() => f()).toThrow('CODE')`.
  Запис `expect(f()).toThrow()` не працює, бо виняток виникає до перевірки.
- **Очікувані значення** задавайте явними числами, а не тією самою формулою, що
  й у коді, інакше тест перевіряє формулу проти себе.
- **Назви тестів** описують поведінку: «обмежує списання 30 % суми», а не
  «тест для applyLoyaltyPoints».
- **Межові значення** перевіряйте трійкою «межа мінус один, межа, межа плюс
  один»: `299/300/301` і `30.14/30.15/30.16`.

## 11. Додаткові команди

```bash
# режим спостереження за змінами
npm run test:watch

# покриття в режимі спостереження
npm run coverage:watch

# лише один файл
npx vitest run tests/loyalty.test.ts

# лише тести за назвою
npx vitest run tests/loyalty.test.ts -t "30 %"

# детальний перелік усіх тестів
npx vitest run --reporter=verbose
```
